Single Django app (`core`) with a flat view-per-feature layout under `core/views/` (auth, dashboard, tenants, stalls, contracts, billing, payments, ledger, notices, reports, settings_views, lookups, audit, users, tenant_portal) all wired through `core/urls.py`. Domain entities live in `core/models.py` (UserProfile, SystemSetting, MarketSection, StallType, Stall, Tenant, RentalContract, Billing, Payment, TenantLedger, Notice, AuditLog) with per-feature subdirectories under `templates/` mirroring the URL space. Cross-cutting concerns are isolated: `core/permissions.py` defines role sets (admin/cashier/supervisor/treasurer/collector/tenant) and decorator factories (`role_required`, `management_required`, `collector_required`, `tenant_isolation_queryset`, `tenant_required`); `core/helpers.py` centralizes business logic (penalty computation, billing generation, tenant login creation, receipt rendering); `core/context_processors.py` injects `system_settings`, `user_role`, `is_collector`, `can_manage_records`, and `STATIC_VERSION` into every template. `core/templatetags/market_tags.py` provides template helpers; `core/management/commands/` exposes admin CLI tasks (apply_penalties, link_tenant_logins, reset_market_data, seed_data). Dependency direction is one-way: views → helpers/permissions/models; templates depend only on context processors and templatetags; no cross-view imports except via shared modules.
