The repository is a single Python/Django application split into two sibling Django apps (`core_app` owning domain models/RBAC/views/reports, `accounts_app` as a placeholder scaffold) plus this root which owns shared configuration: `pyproject.toml` declares the package name `market_rental_system`, pins Django ≥5.0 with psycopg3/PyMySQL dual DB support, whitenoise, reportlab/xhtml2pdf/openpyxl for reporting, and setuptools `find` includes both `core*` and `accounts*`; `manage.py` is the standard Django entry; `vercel.json` defines the production pipeline (Tailwind CSS build → `collectstatic` → rewrite all routes to `/api/index`); `package.json` only drives Tailwind CLI for static assets consumed by the Django templates. Cross-app boundaries are enforced by Django's app registry — `core` exposes domain models and RBAC that `accounts` consumes, while the root holds no business logic.
