## Approach

The repository is a Django application with two independent dependency domains:

- **Python runtime** — managed by **uv** (a fast Python package manager) as the primary tool, with `requirements.txt` kept as a legacy/supplementary manifest.
- **Frontend build tooling** — managed by **npm**, using only devDependencies for Tailwind CSS compilation; no production JS dependencies are shipped.

There is no vendoring of third-party packages. Both ecosystems resolve against public registries (`https://pypi.org/simple` for Python, `https://registry.npmjs.org` for Node). No private registry or `GOPRIVATE`-style configuration exists.

## Key Files

| File | Role |
|---|---|
| `pyproject.toml` | Canonical source of truth for Python project metadata, declared dependencies, and uv config. Declares `requires-python = ">=3.12"`, uses `setuptools.build_meta` as the build backend, and lists runtime deps such as `django>=5.0`, `psycopg[binary]>=3.2`, `whitenoise>=6.8`, `weasyprint`, `reportlab>=4.0`, `xhtml2pdf>=0.2.11`, `pymysql>=1.2.3`, `python-dotenv>=1.2.4`. The `[tool.setuptools.packages.find]` section restricts distribution packaging to `market_rental*`, `accounts*`, `core*`. |
| `uv.lock` | Deterministic lockfile generated by uv. Records exact resolved versions, per-platform wheel URLs, and sha256 hashes for every transitive dependency. Uses `version = 1`, `revision = 3`, and `resolution-markers` to distinguish `python_full_version >= '3.13'` vs `< '3.13'` resolution paths. All sources point at `https://pypi.org/simple`. |
| `requirements.txt` | A minimal, hand-maintained list of top-level Python requirements (no transitive tree, no hashes). It lags behind `pyproject.toml`: e.g., it pins `PyMySQL>=1.1` while `pyproject.toml` pins `pymysql>=1.2.3`, and it omits `python-dotenv` and `django-shortcuts`. This file is not consumed by uv directly but serves as a compatibility surface for tools that still expect `requirements.txt`. |
| `package.json` | Declares only devDependencies: `@tailwindcss/cli ^4.0.0` and `tailwindcss ^4.0.0`. Provides scripts `build:css` and `watch:css` that compile `static/css/input.css` → `static/css/output.css`. The package is marked `private: true`. |
| `package-lock.json` | npm lockfile (lockfileVersion 3) pinning exact versions and integrity hashes for the Tailwind toolchain and its transitive dependencies. |
| `.vercelignore` | Excludes `.venv`, `node_modules`, `credentials.md`, `db.sqlite3`, `media`, `staticfiles`, `*.pyc`, and `__pycache__` from Vercel deployments, ensuring neither Python nor Node dependency trees are shipped to the platform. |
| `market_rental_system.egg-info/` | Legacy setuptools artifact (PKG-INFO, SOURCES.txt, requires.txt, dependency_links.txt) produced by an older install; it is not the active manifest. |

## Architecture and Conventions

1. **Single source of truth for Python deps is `pyproject.toml`**. New Python dependencies should be added there rather than in `requirements.txt`. The `[tool.uv]` section currently declares `dev-dependencies = []` (empty), so all listed dependencies are treated as runtime dependencies.

2. **Deterministic builds via lockfiles**. `uv.lock` is committed alongside the code, providing reproducible installs across environments. The lockfile records both sdist and wheel artifacts with sha256 checksums, and splits resolutions by Python minor version markers.

3. **No vendoring**. Third-party packages are installed into `.venv` (ignored by `.gitignore`) and `node_modules` (excluded from Vercel via `.vercelignore`). There is no `vendor/` directory, no Poetry-style inline hashes in `requirements.txt`, and no custom PyPI index configured.

4. **Dual lockfiles coexist but serve different ecosystems**: `uv.lock` for Python, `package-lock.json` for Node. They are independent and not cross-referenced.

5. **Frontend assets are prebuilt**. `static/js/alpine.min.js` and `static/js/htm x.min.js` are checked-in minified copies of third-party libraries (Alpine.js, htmx); they are not managed through npm. The only npm-managed concern is the Tailwind CLI used to generate `static/css/output.css` from `static/css/input.css`.

6. **Django app discovery is explicit in packaging**. The `[tool.setuptools.packages.find]` include pattern limits what gets bundled when building the egg/distribution, preventing accidental inclusion of test files or unrelated directories.

## Constraints and Rules

- **Python version constraint**: `requires-python = ">=3.12"` in `pyproject.toml` enforces a minimum interpreter version for any environment installing the package.
- **Lockfile must stay in sync with manifests**: `uv.lock` is the authoritative resolved state; running `uv sync` / `uv lock` regenerates it. Committing a stale lockfile would break reproducibility.
- **Vercel deployment excludes dependency trees**: `.vercelignore` explicitly removes `.venv` and `node_modules`, so the platform must run its own install step (e.g., `uv sync` / `pip install -r requirements.txt` and `npm ci`) during build.
- **Legacy `requirements.txt` is not authoritative**: It diverges from `pyproject.toml` on several pins (e.g., `PyMySQL>=1.1` vs `pymysql>=1.2.3`) and omits some deps (`python-dotenv`, `django-shortcuts`). It should not be used as the single source of truth for new changes.
- **No private registry or proxy**: All `source.registry` entries in `uv.lock` point at `https://pypi.org/simple`; no `PYPI_INDEX_URL`, `PIP_INDEX_URL`, or `.npmrc` custom registry is present.
