## Build System Overview

The Market Rental System is a Django application deployed on Vercel. The build pipeline combines Python packaging (uv + setuptools), Node.js-based CSS compilation (Tailwind CLI), and Vercel's serverless deployment.

### Python Dependency Management

Two parallel dependency manifests are maintained:
- `pyproject.toml` — canonical source of truth for project metadata, dependencies, and build configuration. Declares `requires-python = ">=3.12"`, `django>=5.0`, and runtime deps (`dj-database-url`, `psycopg[binary]`, `whitenoise`, `openpyxl`, `weasyprint`, `reportlab`, `xhtml2pdf`, `pymysql`, `python-dotenv`).
- `requirements.txt` — legacy/secondary manifest used by older tooling; it mirrors most but not all of `pyproject.toml` (e.g., missing `django-shortcuts`, different `PyMySQL` version pin).
- `uv.lock` — deterministic lockfile generated by [uv](https://github.com/astral-sh/uv) with `requires-python = ">=3.12"` and resolution markers for `python_full_version >= '3.13'` vs `< '3.13'`, pinning every transitive dependency to exact versions and hashes.

The package is built via setuptools using `[tool.setuptools.packages.find] include = ["market_rental*", "accounts*", "core*"]` and `[build-system] requires = ["setuptools>=61.0"]` with `build-backend = "setuptools.build_meta"`. Version is declared in `pyproject.toml` as `version = "0.1.0"`.

### Frontend Build

CSS is compiled from Tailwind v4 via the CLI tool `@tailwindcss/cli`:
- `package.json` defines two scripts: `build:css` (`tailwindcss -i ./static/css/input.css -o ./static/css/output.css --minify`) and `watch:css` (same command with `--watch`).
- Source stylesheet: `static/css/input.css` → compiled output: `static/css/output.css` (checked into repo).
- No JS bundler; Alpine.js and htmx are served as static files under `static/js/`.

### Vercel Deployment

`vercel.json` configures the entire deploy flow:
- `buildCommand`: runs both frontend and backend steps sequentially: `npm run build:css && python manage.py collectstatic --noinput`.
- `rewrites`: all routes (`/(.*)`) are rewritten to `/api/index`, which is the Vercel serverless entry point defined in `api/index.py`.
- `.vercelignore` exists alongside `.gitignore` to control what gets shipped to Vercel.

There is no Dockerfile, no Makefile, no CI pipeline file (e.g., GitHub Actions, GitLab CI) in the repository. The only automated build hook is the Vercel one.

### Conventions Observed

- **Dual Python manifests**: `pyproject.toml` is the authoritative source (used by uv/setuptools); `requirements.txt` appears to be a legacy artifact kept for compatibility. They drift slightly (e.g., `PyMySQL>=1.1` in requirements.txt vs `pymysql>=1.2.3` in pyproject.toml).
- **Deterministic builds**: `uv.lock` pins every transitive dependency with SHA-256 hashes, ensuring reproducible installs across environments.
- **Static asset pipeline**: Tailwind CSS is compiled at build time and committed (`static/css/output.css` is checked in), so the production build does not require a separate CSS step beyond `collectstatic`.
- **Vercel-first deployment**: The project targets Vercel's serverless runtime exclusively; there is no Docker image or traditional web server (Gunicorn/uWSGI) configured.
- **Django static files**: Whitenoise is listed as a dependency and `collectstatic --noinput` is part of the Vercel build, indicating static assets are collected into a single directory for serving.
- **Package discovery**: Only packages matching `market_rental*`, `accounts*`, `core*` are included in the built distribution, excluding test files and other top-level modules.
